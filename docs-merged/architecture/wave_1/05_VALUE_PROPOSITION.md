# Rilavo Product — Value Proposition (E-05)

**Tree:** Product
**Wave:** 1 — System Foundation
**Status:** Decided (direction); Open (exact numbers)
**Depends on:** E-03, E-04
**Closes when:** A real customer runs the ROI comparison below using their own numbers, not Rilavo's projected ones.

## The measurable outcomes, stated as claims a customer can check, not as marketing copy

- Reduced fraud loss from unauthorized agent action
- Reduced manual-review and allowlisting engineering hours
- Higher legitimate-agent success rate — fewer false blocks of traffic that should have been accepted
- Reduced liability exposure from accepting agent traffic without a defensible verification record

## The ROI test this document commits to

A customer should be able to run this comparison using only their own numbers, without needing to trust anything Rilavo says about itself:

> Cost of building agent-authorization verification internally, plus the residual fraud rate that persists without it, **versus** Rilavo's usage-based fee.

If that comparison can't be constructed independently by the customer's own team, the value proposition isn't real yet — it's a claim waiting on evidence. This document does not currently have real-world numbers to plug into that formula; that gap is explicitly Open, not glossed over with a projected figure that would just be invented for the sake of looking complete.

## Why this is the right test, not just a convenient one

A value proposition that only works if the customer trusts Rilavo's own account of its impact is a weak one — it's exactly the kind of claim a skeptical technical buyer (E-03) is trained to discount. A value proposition built so the customer can verify it independently, using data they already have, survives that skepticism instead of hoping to avoid it.
