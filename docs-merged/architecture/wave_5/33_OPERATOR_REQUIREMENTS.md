# Rilavo Protocol — Operator Requirements (P-33)

**Tree:** Protocol
**Wave:** 5 — Governance & Institutionalization
**Status:** Deferred
**Depends on:** P-24
**Closes when:** Same trigger as P-16 — a real applicant, since the two documents are gated by the same fact and shouldn't be treated as independently resolvable in the meantime.

## Relationship to P-16

P-16 covers what a *node* needs to run correctly. This document covers what an *organization* running that node needs to demonstrate to be admitted — legal standing, operational accountability, willingness to be bound by the governance process (P-24) and the ethics boundary (P-40). Closely related, deliberately kept as separate documents because "can this software run correctly" and "should this organization be trusted to run it" are different questions, even though both are currently gated on the same missing fact: a real applicant.

## What's honestly known now

The admission *process* (P-24) applies regardless of who the applicant is. What's not known: the specific organizational bar — how much operating history is enough, what accountability commitments are required, whether individual operators (not just organizations) should be eligible at all.

## What this document refuses to invent

A specific legal-entity requirement, a minimum-capitalization bar, or a named certification standard — none have justification yet, and inventing them now risks encoding assumptions (for instance, that only well-capitalized organizations should qualify) that would themselves need to be checked against Principle 5's commitment to a genuinely open protocol, not silently assumed as acceptable gatekeeping.

## What would change this document

The same trigger as P-16: a real applicant, at which point this document and P-16 both get written for real, informed by the actual profile of who's applying rather than a hypothetical one.
