# Rilavo Protocol — Node & Operator Specification (P-16)

**Tree:** Protocol
**Wave:** 5 — Governance & Institutionalization
**Status:** Deferred — genuinely, not provisionally
**Depends on:** P-15, P-24
**Closes when:** A second operator actually applies through the admission process now specified in P-24.

## Why this stays gated rather than getting a Wave-2-style deep specification

P-24 now specifies *how* an operator would be evaluated — the process. This document would specify the *specific bar* an operator has to clear. Writing that bar in detail before a single real applicant exists means guessing at requirements with no real case to calibrate them against — precisely the manufactured-precision failure mode this project has avoided everywhere else, and no more acceptable here just because it would make this document feel more complete.

## What can honestly be said now — categories, not thresholds

Any future bar will plausibly cover: security posture (key custody comparable to P-12's own standard), operational commitment (uptime and incident-response capability comparable to what E-12/E-13 promise customers), and data-handling compliance (consistency with the privacy architecture, P-13). These are categories worth naming so P-24's review process has something to evaluate against in shape, even though the specific pass/fail line in each category isn't set.

## What this document explicitly refuses to invent

A numeric uptime requirement, a specific security certification demand, a minimum operating history — none of these have real justification yet, and setting them now would risk either being needlessly exclusionary (blocking a legitimate small operator) or needlessly permissive (admitting one that shouldn't clear a bar nobody has actually tested).

## What would change this document

A real, serious application from a prospective second operator. At that point, this document stops being a placeholder and becomes the actual output of running P-24's admission process for the first time — informed by a real case rather than a hypothetical one.
