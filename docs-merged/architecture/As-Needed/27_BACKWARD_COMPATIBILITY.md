# Rilavo Protocol — Backward Compatibility (P-27)

**Tree:** Protocol
**Wave:** Continuous / As-Needed
**Status:** Deferred, honestly empty
**Depends on:** P-26
**Closes when:** Opens at the first v1 release — there is no prior version to be compatible with yet, and no amount of writing changes that.

## Why this stays short

Every claim this document could make right now would be about a version that doesn't exist. Padding it with speculative compatibility guarantees for a hypothetical future format would be worse than an honest placeholder — it would let a reader mistake invented detail for a real commitment.

## What is decided, minimally

Per P-26's versioning policy: breaking changes require a new major version verifiers opt into, never a silent change applied to an existing one. Whatever backward-compatibility guarantees exist for the first real version transition inherit directly from that policy — this document doesn't need a separate principle, only the record of how that policy was actually exercised the first time it mattered.

## What would change this decision

The first real breaking change to the credential format, once it happens — at which point this document records what compatibility was actually preserved, for how long, and under what conditions, rather than promising any of that in advance of having a real case to describe.
