# Migration Guide: v0.0.x → v0.1.0

This guide covers the breaking changes and migration steps required to upgrade from pre-release versions (v0.0.x) to v0.1.0.

## Overview

v0.1.0 is the first stable release of the Rilavo protocol. It introduces several breaking changes to align with the finalized protocol specification.

## Breaking Changes

### 1. Credential Format (P-06)

**Before**: Credential used `ver` field explicitly set to 1
**After**: Credential omits `ver` field entirely (implicit v1)

```json
// v0.0.x (old)
{
  "ver": 1,
  "iss": "rilavo:iss:...",
  "sub": "acme-corp:runner-01",
  ...
}

// v0.1.0 (new)
{
  "iss": "rilavo:iss:...",
  "sub": "acme-corp:runner-01",
  ...
}
```

**Migration**: Remove `"ver": 1` from all credential issuance code. The verifier treats absent `ver` as version 1.

### 2. Action Class Exact Match (P-07)

**Before**: Action class supported wildcard matching (`data.*` matched `data.read`)
**After**: Exact string match required

```python
# Before
action_class = "data.*"  # matched data.read, data.write

# After
action_class = "data.read"  # exact match only
```

**Migration**: Update all action class strings to exact values. Update any wildcard logic.

### 3. Audience Binding Enforcement (P-07)

**Before**: Audience check was optional
**After**: Audience check is mandatory and must match exactly

```python
# Before (optional)
if credential.audience != expected_audience:
    warn("Audience mismatch")

# After (mandatory - fail-closed)
if credential.audience != expected_audience:
    return Reject("audience_mismatch")
```

**Migration**: Ensure all verifiers pass the expected audience and enforce exact match.

### 4. Proof-of-Possession Domain Separation (P-07)

**Before**: PoP payload used simple concatenation
**After**: PoP uses domain-separated `rilavo_pop_v0` format

```python
# Before
payload = f"{method}:{path}:{action}:{nonce}"

# After (domain-separated)
body = {"method": method, "path": path, "act": action, "nonce": nonce}
digest = sha256(canonicalize(body))
payload = canonicalize({"rilavo_pop_v0": digest.hex()})
```

**Migration**: Update all PoP signing/verification code to use domain-separated format.

### 5. Key Rotation with Overlap Window (P-12)

**Before**: Immediate key rotation
**After**: Overlap window with retroactive compromise cutoff

```python
# Before
directory.publish(new_key)  # Immediate switch

# After
directory.publish(new_key, valid_from=now, overlap_window=86400)  # 24h overlap
# Old key remains valid for overlap period
```

**Migration**: Implement overlap window in key directory publishing.

### 6. Revocation Log Format (P-09)

**Before**: Simple list of revoked nonces
**After**: Append-only hash-chained log with fail-closed semantics

```python
# Before
revoked = set(["nonce1", "nonce2"])

# After
revocation_log = RevocationLog()
revocation_log.append("nonce1", revoked_by="issuer")
# Verification fails if log unavailable (fail-closed)
```

**Migration**: Migrate to hash-chained revocation log.

## Migration Steps

### 1. Update Issuance Code
```python
# Remove ver field from issuance
cred = issuer.issue_credential(
    principal="acme-corp",
    agent="agent-1",
    agent_public_key=agent_pub,
    action_class="data.read",  # Exact match
    audience="verifier:api.example.com"
)
```

### 2. Update Verification Code
```python
# Ensure audience is passed and enforced
result = do_verify(
    verifier_id="verifier:api.example.com",
    credential=cred,
    request=request,
    directory=directory,
    revocations=rev_log,
    nonces=nonce_cache
)
```

### 3. Update PoP Signing
```python
# Use domain-separated PoP payload
pop_sig = sign_pop(agent_key, method, path, action_class, nonce)
# Uses domain-separated format internally
```

### 4. Update Key Directory
```python
# Publish with overlap window
directory.publish(issuer_key_entry, overlap_seconds=86400)
```

## SDK-Specific Migration

### Python SDK
```bash
pip install --upgrade rilavo
# Update imports if needed
from rilavo.api import Issuer, do_verify
```

### TypeScript SDK
```bash
npm update @rilavo/sdk
# Update imports
import { Issuer, Verifier } from "@rilavo/sdk"
```

### Go SDK
```bash
go get github.com/rilavo/rilavo-go@latest
# Update imports
import "github.com/rilavo/rilavo-go"
```

### Next.js Middleware
```bash
npm update @rilavo/next
# Update middleware config
import { withRilavo } from "@rilavo/next"
```

### WordPress Plugin
1. Download latest `rilavo-mu.zip` from releases
2. Upload via WordPress Admin → Plugins → Add New → Upload Plugin
3. Update settings in WordPress Admin → Settings → Rilavo Verification

## Verification

After migration, run the conformance tests:

```bash
# Run all conformance tests
rilavo-conformance --sdks ts go nextjs wp py

# Or run per-SDK
npm test        # TypeScript
go test ./...   # Go
npm test        # Next.js
composer test   # WordPress (if PHPUnit configured)
uv run pytest   # Python
```

All tests should pass with byte-for-byte parity against golden vectors.

## Rollback Plan

If issues arise:

1. **Rollback SDK version**: Pin to previous version in package manager
2. **Rollback credential format**: Re-add `ver: 1` temporarily (verifier accepts both)
3. **Rollback audience check**: Temporarily disable (not recommended for production)
4. **Rollback PoP format**: Temporarily support both formats

Note: The verifier in v0.1.0 accepts credentials with **absent `ver`** (treats as v1) and **explicit `ver: 1`** for backward compatibility during transition.
